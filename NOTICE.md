## 6. What this fork changes about the build

* The autotools build (`configure.ac`, `Makefile.am`, the `m4/` macros) is
  left in place and untouched, and still works for anyone who wants it.
  This fork does not use it; `README.md` says what each build does.
* `config.h` and `htscodecs/version.h` are generated by `build.zig` instead
  of by autoconf and `git describe`.  Both are listed in upstream's
  `.gitignore` and are not part of the distributed tree.
* `-Dlinkage=static|dynamic` selects the installed artifact.  The default is
  `static`, which is what this build did before the option existed:
  `std.Build.LibraryOptions.linkage` defaults to `.static` and htscodecs'
  `build.zig` never set it.  The shared variant's ABI triple is libtool's
  `-version-info 3:12:1` from `configure.ac`, which is ABI 2 — it is not the
  release version and is never presented as one.
* bzip2 support is off unless the build is given `-Dbz2=true`, matching
  upstream's behaviour on a machine without libbz2.  The Nix derivation keeps
  the same default by taking `bzip2` as `null`; nothing enables it
  implicitly.
* On `wasm32-wasi` the library is built with `NO_THREADS`, selecting
  upstream's own non-pthread fallback for its scratch pools.
* The per-ISA 32x16 kernels are separate objects, compiled PIC only for the
  shared variant so the static archive stays byte-for-byte what it was.
* `package.nix`, `flake.nix`, `devenv.nix`, `devenv.yaml` and `.envrc`
  package the same build for Nix.  They add no library, no flag and no
  feature: `zig build install` is the only install path, and the derivation
  copies no licence or documentation file, because the build installs them.
* Continuous integration points at this fork's own workflow, not at
  upstream's Cirrus CI.
